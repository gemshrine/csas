# Доменная модель

Здесь описана согласованная предметная модель. Её JPA-сущности и схема базы
сопровождаются отдельно в коде и миграциях.

## Четыре агрегата

**Агрегат** это то, что загружается, проверяется и сохраняется целиком, потому
что внутри него живёт правило. Остальное является справочником или отчётом.

### Курс

- **Определяется:** дисциплина + группа + тип курса + семестр начала + семестр
  окончания
- **Типы:** `LECTURE`, `SEMINAR`, `COURSEWORK`
- **Хранит:** одного преподавателя, семестр начала, семестр окончания и состояние
  (`ИДЁТ` / `ЗАВЕРШЁН`)
- **Период:** семестры начала и окончания могут совпадать или различаться. Для
  каждой группы период каждого типа курса определяется отдельно.
- **Преподаватель:** назначается на конкретный курс. Один преподаватель может
  вести несколько типов курсов одной или разных дисциплин.
- **Данные по типам:** семинарный курс хранит работы и баллы; лекционный курс
  связан с ведомостью посещаемости; курсовой курс связан с отдельной ведомостью
  курсовых работ.
- **Операции:** семинарный курс позволяет добавить, изменить или удалить работу
  и выставить балл. Курс любого типа можно завершить преподавателем этого курса.
- **Инварианты семинарного курса:**
  1. любое изменение возможно только в состоянии `ИДЁТ`
  2. балл лежит в диапазоне от 0 до максимума работы
  3. добавленная работа сразу даёт 0 всем студентам курса
  4. семинарный курс можно завершить, только если в нём есть работа. Лекционный
     и курсовой курсы завершаются без работ семинарной части.
- **Вычисляет:** рейтинг студента от 0 до 100 только для семинарного курса

### Ведомость посещаемости

- **Относится к:** лекционному курсу (`LECTURE`)
- **Хранит:** состояние (`ОТКРЫТА` / `ЗАКРЫТА` / `АРХИВ`); лекции курса;
  отметку `был` / `не был` для каждого студента на каждой лекции
- **Операции:** добавить лекцию · отметить посещаемость · закрыть ·
  архивировать
- **Инварианты:**
  1. лекции добавляет и посещаемость отмечает только преподаватель курса
  2. отметку можно изменить только пока ведомость открыта и курс идёт
  3. для студента может быть только одна отметка на конкретной лекции
  4. закрыть ведомость можно после завершения курса и заполнения всех отметок
  5. посещаемость не влияет на рейтинг и итоговую оценку; решение о последствиях
     пропусков принимает вуз вне системы

### Зачётная ведомость

- **Относится к:** семинарному курсу (`SEMINAR`)
- **Хранит:** состояние (`ОТКРЫТА` / `ЗАКРЫТА` / `АРХИВ`); результат контроля
  по каждому студенту (балл от 0 до 100, либо зачёт/незачёт, либо «не внесён»);
  зафиксированную при закрытии шкалу перевода
- **Операции:** внести результат · закрыть · переоткрыть *(деканат)* ·
  архивировать
- **Инварианты:**
  1. открыть можно только ведомость завершённого курса
  2. результат вносит преподаватель этого семинарного курса
  3. вносить результаты можно только в состоянии `ОТКРЫТА`
  4. нельзя закрыть, пока результат не внесён для каждого студента курса
  5. из `АРХИВ` переходов нет

### Ведомость курсовых работ

- **Относится к:** курсовому курсу (`COURSEWORK`)
- **Хранит:** состояние (`ОТКРЫТА` / `ЗАКРЫТА` / `АРХИВ`) и балл от 0 до 100 для
  каждого студента
- **Вычисляет:** результат по фиксированным границам: от 85 до 100 это `5`, от
  70 до 84 это `4`, от 50 до 69 это `3`, ниже 50 это `НЕ СДАНО`
- **Операции:** внести или изменить балл · закрыть · переоткрыть для пересдачи
  в следующем семестре · архивировать
- **Инварианты:**
  1. балл находится в диапазоне от 0 до 100
  2. ведомость нельзя закрыть, пока балл не внесён каждому студенту курса
  3. балл вносит преподаватель курсового курса, пока ведомость открыта
  4. переоткрытие закрытой ведомости для пересдачи выполняет деканат в следующем
     семестре
  5. результат курсовой работы не входит в рейтинг семинарного курса и не
     изменяет результат экзамена или зачёта

### Итоговая ведомость

- **Строится из:** рейтинга студента в курсе, результата контроля из
  зачётной ведомости и зафиксированной шкалы перевода
- **Содержит:** итог по дисциплине для каждого студента
- **Правила расчёта:** для обычного зачёта переносит `зачёт` / `незачёт`; для
  экзамена и дифференцированного зачёта усредняет рейтинг и результат контроля,
  после чего переводит итоговый балл в оценку от 2 до 5
- **Хранение:** является отчётом/представлением и отдельно не дублирует
  вычисляемые итоги

Результат курсовой работы отображается отдельно и не входит в итог,
рассчитываемый по семинарному рейтингу и зачётной ведомости.

## Справочники

Обычный CRUD, без собственной логики. 

- **Студент:** ФИО, дата рождения, пол, контакты, форма обучения, дата
  поступления, статус (учится / академ / отчислен), текущая группа
- **Группа:** название, специальность, курс, форма обучения, год набора
- **Дисциплина:** название, описание, часы (лекции/практики/лабораторные),
  форма контроля (экзамен / диф. зачёт / зачёт)
- **Преподаватель:** ФИО, кафедра, должность, учёная степень, контакты
- **Семестр:** учебный период; курс ссылается на семестр начала и окончания

## Операции, которые не принадлежат ни одному агрегату

**Перевод студента в другую группу** затрагивает две группы и задолженности
студента, то есть выходит за границы любого агрегата. Оформляется как сценарий
уровня приложения: проверяет отсутствие задолженностей и то, что семестр
завершён, затем меняет группу.

## Отчёты

Ничего не хранят, строятся запросами:

- ведомость по группе и дисциплине (распечатка баллов курса);
- ведомость посещаемости по группе, дисциплине и лекциям;
- сводная успеваемость студента за всё обучение, включая прошлые группы;
- рейтинговый список группы;
- должники;
- статистика по группам, курсам, специальностям;
- качество знаний (доля оценок «4» и «5»).

## Чего в модели намеренно нет

- **Оценка как самостоятельная сущность.** Балл существует только внутри курса,
  результат хранится только внутри ведомости. Иначе правила «только пока курс идёт» и
  «только закреплённый преподаватель» негде проверять.
- **Сводная ведомость студента как хранимая таблица.** Всё её содержимое
  выводится из курсов и ведомостей. Хранить его отдельно значит дублировать.
- **Средний балл студента по всем дисциплинам.** Система показывает рейтинг и
  результат отдельно по каждому курсу.
- **Сдача заданий студентом** (загрузка файлов, сроки, проверка). Это LMS,
  задание такого не требует.
- **Куратор группы.** В текущем объёме система не хранит куратора и не задаёт для
  него сценариев работы.
- **Решение о последствиях пропусков лекций.** Система предоставляет данные о
  посещаемости; решение о стипендии или отчислении остаётся за вузом.
- **Расписание.** Отдельная предметная область, с успеваемостью не связана
  ни одним правилом.
