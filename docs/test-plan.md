# План тестирования

## Назначение

План описывает ручную проверку основных пользовательских сценариев системы перед защитой. Проверки выполняются через браузер, без консоли разработчика и прямых запросов к API.

Результаты и замечания по фактически выполненным проверкам фиксируются отдельно в [manual-testing.md](manual-testing.md). Наличие сценария в этом плане не означает, что он уже пройден.

## Условия проведения

Приложение запускается с профилем `dev` по инструкции из [development.md](development.md), проверки выполняются на локальной dev-базе, поскольку миграции тестовых данных меняют схему `public`. Для входа используются демонстрационные учётные записи и пароли из `development.md`. Для операций, меняющих данные, создаются отдельные тестовые записи с заметным названием, например `ТЕСТ-ПЛАН-<номер>`, без изменения общих демонстрационных данных. Проверка таймаута сессии требует более пяти минут без действий в приложении. При проверке резервной копии загруженный файл нужно сохранить отдельно и не выполнять восстановление поверх рабочей базы.

## Сценарии

| --- | --- | --- | --- |
| TC-01 | Вход, гость | Открыть закрытую страницу, например `/courses` | Приложение перенаправляет на страницу входа и сохраняет адрес запрошенной страницы |
| TC-02 | Вход, все роли | Войти по очереди под студентом, преподавателем, деканатом и администратором | Вход успешен, открывается доступная роли начальная страница |
| TC-03 | Вход, гость | Ввести правильный логин и неверный пароль | Вход отклонён, сообщение не раскрывает пароль или иные секретные данные |
| TC-04 | Вход, администратор | Отключить тестовую учётную запись, затем попробовать войти под ней | Вход отклонён, учётная запись остаётся отключённой |
| TC-05 | Выход, вошедший пользователь | Нажать «Выйти», затем открыть закрытую страницу | Сессия завершена, приложение требует войти снова |
| TC-06 | Таймаут сессии, вошедший пользователь | Войти, не выполнять запросов более пяти минут, затем открыть страницу | Сессия истекла, требуется повторный вход |
| TC-07 | Учётные записи, администратор | Создать учётную запись с ролью деканата | Новая запись появляется в списке как активная, вход под ней работает |
| TC-08 | Учётные записи, администратор | Назначить тестовым пользователям роли преподавателя и студента с выбором профиля | В таблице показываются фамилия и инициалы профиля, созданные пользователи могут войти |
| TC-09 | Учётные записи, администратор | Изменить логин или роль пользователя, у которого открыта сессия | Данные обновлены, прежняя сессия пользователя отозвана |

| TC-11 | Учётные записи, администратор | Удалить отдельную тестовую учётную запись и попробовать войти под ней | Запись исчезает из списка, вход невозможен |

| TC-13 | Разграничение доступа, все роли | Открыть страницы и данные, не предназначенные для текущей роли; студентом попробовать открыть чужую успеваемость | Доступ запрещён, студент видит только собственные результаты |
| TC-14 | Группы, деканат | Изменить данные тестовой группы и назначить ей активного пользователя деканата куратором | Изменения сохраняются, куратор отображается у группы |
| TC-15 | Создание курсов, деканат | Создать для тестовой группы курсы типов `LECTURE`, `SEMINAR` и `COURSEWORK`, назначить преподавателей и периоды | Курсы создаются раздельно, для каждого отображаются свой тип, преподаватель и семестры начала и окончания |
| TC-16 | Курс, деканат | Изменить преподавателя незавершённого тестового курса и сохранить изменения | На странице курса и в списке отображается новый преподаватель |
| TC-17 | Курс, деканат | Удалить пустой тестовый курс, затем попробовать удалить завершённый курс | Пустой курс удаляется, удаление завершённого курса отклоняется |
| TC-18 | Курс, деканат | Переоткрыть завершённый курс в следующем семестре | Курс снова доступен для работы, период продлён, ранее созданные работы и баллы сохранены |
| TC-19 | Семинарная работа, преподаватель | Добавить работу с максимальным баллом в семинарный курс | Работа появляется в курсе, всем студентам курса назначено 0 баллов за неё |
| TC-20 | Рейтинг, преподаватель | Создать работы с максимумами 15, 5 и 20, выставить одному студенту 10, 0 и 20 баллов | Рейтинг студента равен 75 процентам и обновляется после изменения балла |
| TC-21 | Баллы, преподаватель | Выставить 0 и максимальный балл за работу, затем попробовать отрицательный балл и балл выше максимума | Допустимые значения сохраняются, недопустимые отклоняются с понятным сообщением |
| TC-22 | Успеваемость, студент | Открыть свои курсы и страницу семинарного курса с работами | Отображаются свои баллы, рейтинг и результаты контроля; данные других студентов не показываются |
| TC-23 | Экзамен и дифзачёт, преподаватель и студент | Для тестового семинарного курса получить рейтинг 93, внести 80 баллов за экзамен; повторить для дифзачёта | Итоговый балл равен 86 после округления вниз; итоговая оценка соответствует настроенной шкале и видна студенту |
| TC-24 | Зачёт, преподаватель и студент | Внести студенту «зачёт», другому «незачёт» в ведомость обычного зачёта | Результаты переносятся в итоговую ведомость без усреднения с рейтингом |
| TC-25 | Зачётная ведомость, преподаватель | Попробовать закрыть ведомость с незаполненными результатами, заполнить результаты всем студентам и закрыть её | До полного заполнения закрытие отклоняется; после заполнения ведомость закрывается, итоговые результаты доступны студентам |

| TC-29 | Посещаемость, преподаватель | Попробовать закрыть ведомость незавершённого курса и ведомость с пропущенными отметками; завершить курс и заполнить все отметки | Закрытие до выполнения условий отклоняется; после завершения курса и заполнения ведомость закрывается |

## Проверка интерфейса

При проверке интерфейса следует убедиться, что страницы и сообщения отображаются на русском языке, а каждой роли доступны только предназначенные ей разделы. Страница без входа должна перенаправлять на форму авторизации. Поля должны иметь понятные подписи, ошибки должны сопровождаться сообщениями и не приводить к сохранению недопустимых значений. После успешного сохранения должны отображаться обновлённые данные. Таблицы должны иметь заголовки и понятное состояние при отсутствии записей. На странице курса должны показываться только действия, относящиеся к его типу, а закрытые и архивные ведомости не должны предлагать недоступные изменения. Отчёты и резервная копия должны скачиваться кнопками интерфейса, после выхода пользователь должен возвращаться на страницу входа.

## Критерии завершения

План включает не менее 30 сценариев и матрицу покрытия функциональных требований. Для проведённых проверок фиксируются фактические результаты, ошибки, отличия от ожидаемого поведения и повторные проверки в [manual-testing.md](manual-testing.md). Непроведённые проверки не указываются как успешные; для обнаруженных проблем записывается задача или обоснованное ограничение. Протокол испытаний содержит дату, окружение, результаты выполненных тестов, найденные дефекты и итоговое заключение.
