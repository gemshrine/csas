# Локальная разработка

## Запуск с демонстрационными данными

Dev-профиль нужен для локальной разработки и демонстрации API. Он добавляет отдельную схему PostgreSQL `csas_dev`, запускает в ней обычные миграции и отдельную миграцию с тестовыми данными. Основная схема `public` этим профилем не используется и не изменяется.

### Первый запуск

Из корня проекта создай локальный файл настроек и запусти приложение:

```bash
cp .env.example .env
./mvnw spring-boot:run -Dspring-boot.run.profiles=dev
```

Spring Boot поднимет PostgreSQL и pgAdmin из `compose.yaml`, если они ещё не запущены. Приложение подключится к той же базе, что указана в `.env`, но будет работать в схеме `csas_dev`. Если контейнеры уже запущены, повторно запускать Docker Compose не нужно.

При первом старте Flyway создаст таблицы в `csas_dev` и добавит демонстрационный курс. При следующих стартах миграции повторно не выполняются, а внесённые вручную изменения сохраняются.

### Запуск из IntelliJ IDEA

Открой конфигурацию запуска `CsasApplication` и укажи в поле **Program arguments**:

```text
--spring.profiles.active=dev
```

Либо задай переменную окружения `SPRING_PROFILES_ACTIVE=dev`. Не указывай оба способа одновременно.

### Демонстрационные пользователи

| Логин | Роль | Пароль |
|-------|------|--------|
| `demo-dean` | деканат | `demo1234` |
| `demo-seminar` | преподаватель семинарской части | `demo1234` |
| `demo-lecture` | преподаватель лекционной части | `demo1234` |
| `demo-student` | студент | `demo1234` |

Эти пароли предназначены только для локальной разработки. Не используй их в production и не добавляй реальные данные в dev-миграцию.

Для проверки API открой `docs/api.md`: там описаны получение CSRF-токена, вход через `/api/auth/login`, текущая учётная запись и выход. Браузер должен сохранять и отправлять cookies сессии. Сессия завершается после пяти минут бездействия.

### Что хранится в демонстрационных данных

В `csas_dev` создаются учётки всех четырёх ролей, один связанный со студентом курс, преподаватели семинарской и лекционной частей, работа с баллом, открытая экзаменационная ведомость с результатом, а также ведомость посещаемости с лекцией и отметкой.

Миграция с демонстрационными данными находится в `src/main/resources/db/dev`. Она подключается только при активном профиле `dev`. Не переноси её в `db/migration`: обычный запуск приложения не должен создавать тестовых пользователей.

Если нужны чистые демонстрационные данные, используй отдельную локальную базу или схему и настрой подключение через `.env`. Не удаляй схему `csas_dev` в общей базе команды: там могут быть данные других разработчиков.

## Серверные страницы

MVC-контроллер `SheetPageController` передаёт данные ведомостей в `Model`. Их HTML-шаблоны разрабатывает Kabangames. JSON-контракты остаются в контроллерах под `/api/**`.

| Страница | URL | Model attribute | Доступ |
|----------|-----|-----------------|--------|
| Контрольная ведомость | `/control-sheets/{sheetId}` | `sheet` | Преподаватель семинарской части или деканат |
| Ведомость посещаемости | `/attendance-sheets/{sheetId}` | `sheet` | Преподаватель лекционной части или деканат |

Контроллеры используют те же сервисы чтения и проверки доступа, что и API. Запись и изменение данных выполняются через существующие API-маршруты.

## Обычный запуск

Чтобы запустить приложение без демонстрационных записей, выполни:

```bash
./mvnw spring-boot:run
```

Без активного `dev`-профиля приложение использует основную схему базы и не применяет dev-миграцию с тестовыми данными.
