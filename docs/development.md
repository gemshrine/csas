# Локальная разработка

## Запуск с демонстрационными данными

Dev-профиль нужен для локальной разработки и демонстрации API. Он использует ту же базу и схему `public`, что и обычный запуск, и добавляет демонстрационные записи в общие таблицы.

### Первый запуск

Из корня проекта создай локальный файл настроек и запусти приложение:

```bash
cp .env.example .env
./mvnw spring-boot:run -Dspring-boot.run.profiles=dev
```

Spring Boot поднимет PostgreSQL и pgAdmin из `compose.yaml`, если они ещё не запущены. Приложение подключится к базе из `.env` и будет работать в схеме `public`. Если контейнеры уже запущены, повторно запускать Docker Compose не нужно.

При первом старте Flyway создаст таблицы и тестовый набор данных в `public`. Затем приложение добавит демонстрационные записи, если учётка `demo-dean` ещё не существует. При следующих стартах записи повторно не добавляются, а внесённые вручную изменения сохраняются.

Dev-профиль меняет данные в основной схеме `public`. Не запускай его против production или общей базы, если в ней нельзя создавать тестовые записи.

### Запуск из IntelliJ IDEA

Открой конфигурацию запуска `CsasApplication` и укажи в поле **Program arguments**:

```text
--spring.profiles.active=dev
```

Либо задай переменную окружения `SPRING_PROFILES_ACTIVE=dev`. Не указывай оба способа одновременно.

### Демонстрационные пользователи

| Логин | Роль | Пароль |
|-------|------|--------|
| `demo-dean` | деканат | `demo1234` |
| `demo-seminar` | преподаватель семинарской части | `demo1234` |
| `demo-lecture` | преподаватель лекционной части | `demo1234` |
| `demo-student` | студент | `demo1234` |

Для проверки API управления учётными записями используй `lab1-test-admin` с
паролем `demo1234`.

Миграция также создаёт учётки `lab1-test-admin`, `lab1-test-dean`,
`lab1-test-teacher-01` … `lab1-test-teacher-10` и `lab1-test-student-01` …
`lab1-test-student-20`. Их пароль тоже `demo1234`.

Эти пароли предназначены только для локальной разработки. Не используй их в production и не добавляй реальные данные в dev-миграцию.

Для проверки API открой `docs/api.md`: там описаны получение CSRF-токена, вход через `/api/auth/login`, текущая учётная запись и выход. Браузер должен сохранять и отправлять cookies сессии. Сессия завершается после пяти минут бездействия.

При открытии страницы без входа приложение перенаправляет на `/login`. После успешного входа пользователь возвращается на запрошенную страницу. Если адрес не был сохранён, студент переходит к своим курсам, преподаватель и деканат к списку курсов. Для API сохраняется ответ `401` в JSON, редиректа на страницу входа нет.

Для быстрой проверки в браузере открой `/me` при запущенном `dev`-профиле. Страница позволяет войти демо-пользователем и перейти к доступным ведомостям. Она не используется в обычном профиле.

### Что хранится в демонстрационных данных

В `public` создаются 20 студентов, 5 групп, 15 дисциплин, 10 преподавателей,
240 баллов за семинарные работы, курсы трёх типов, контрольные и курсовые
результаты, посещаемость лекций и учётки для проверки ролей. Кроме этого
добавляется небольшой демонстрационный набор: семинарный, лекционный и курсовой
курсы одной дисциплины, открытая экзаменационная ведомость и курсовая ведомость
с баллом 70.

Основной тестовый набор находится в `src/main/resources/db/dev/migration` и
применяется Flyway только при активном профиле `dev`. Дополнительные
демонстрационные записи находятся в `src/main/resources/db/dev/demo-data.sql`.
Обычный запуск приложения не создаёт тестовых пользователей.

В тестовом наборе по одному семинарному курсу каждой группы оставлено в статусе
`IN_PROGRESS`, остальные семинарные курсы имеют статус `COMPLETED`. Так можно
проверять и текущую работу преподавателя, и завершённые курсы с ведомостями.
Демонстрационный семинарный курс для `DEMO-301` остаётся завершённым.

## Серверные страницы

MVC-контроллеры возвращают страницы и передают данные в `Model`. JSON-контракты и команды изменения данных остаются под `/api/**`; браузерная страница использует их через JavaScript.

| Страница | URL | Представление и данные | Доступ |
|----------|-----|----------------------|--------|
| Вход | `/login` | `login` | Все |
| Курсы преподавателя или деканата | `/courses` | `courses`, модель `courses` | Преподаватель или деканат |
| Курс, работы и рейтинг | `/courses/{courseId}` | `course`, модель `course` | Преподаватель семинарской части или деканат |
| Переоткрытие завершённого курса | `POST /courses/{courseId}/reopen` | Перенаправление на страницу курса | Деканат |
| Курсы студента | `/me/courses` | `student/courses`, модель `courses` | Студент |
| Успеваемость студента по курсу | `/me/courses/{courseId}` | `student/course`, модель `course` | Студент курса |
| Контрольная ведомость | `/control-sheets/{sheetId}` | `control-sheet`, модель `sheet` | Преподаватель семинарской части или деканат |
| Посещаемость лекций | `/attendance-sheets/{sheetId}` | `attendance-sheet`, модель `sheet` | Преподаватель лекционной части или деканат |
| Справочники | `/groups`, `/students`, `/teachers`, `/disciplines`, `/semesters` | `catalog/{type}`, модели `catalogType`, `items`, `item` | Деканат |
| Данные элемента справочника | `/{type}/{id}` для перечисленных справочников | `catalog/{type}`, модели `catalogType`, `items`, `item` | Деканат |

Контроллеры используют те же сервисы чтения и проверки доступа, что и API. HTML-шаблоны пользовательских страниц реализуются в рамках issue #28. Dev-страница `/me` существует только для быстрой локальной проверки.

## Обычный запуск

Чтобы запустить приложение без демонстрационных записей, выполни:

```bash
./mvnw spring-boot:run
```

Без активного `dev`-профиля приложение использует основную схему базы, но не добавляет демонстрационные записи.
